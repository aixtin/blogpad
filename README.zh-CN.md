# BlogPad

一个极简的安卓写作台：在手机上写 Markdown，通过 SSH 直接发布到 Hugo 站点。

写完点发布，App 把 Markdown 文件通过 SFTP 传到站点的内容目录，在服务器上执行构建命令，
然后返回文章链接。没有 CMS、没有数据库、不依赖任何第三方服务，只需要一台能 SSH 的服务器和
一个基于文件（Git）的站点。

## 功能

- **文章列表为入口** —— 首页即服务器 `content/post` 的投影：标题、日期、草稿状态、标签；
  下拉刷新，点条目进入编辑；搜索按需展开，新建按钮固定在右下角。
- **编辑已有文章** —— 读远端 `.md` 回填，保存时原地覆盖；slug 改了就在远端改名并清理旧文件；
  不归应用管的 front matter 键原样保留。
- **写作与发布拆成两步** —— 编辑页只有标题、正文和附件；点右上角「完成」进入独立的发布页，
  在那里填 slug、分类、标签、封面。分类和标签只列服务器上已有的，点选即用，不预选——
  新文章不是上一篇文章的复制品。
- **自动生成 Hugo front matter** —— `title`、`date`、`draft`、`slug`、`categories`、`tags`
  由 App 写入（选了封面还会写 `image`），文件可直接被 Hugo 识别，无需手工拼头信息。
- **附件等你发布时才上传** —— 选中的文件先复制进应用私有暂存区，正文光标处只留一条占位引用，
  服务器上什么都不动。点发布时才一次性上传全部附件，把占位替换成站内地址，再写 `.md`、
  再构建；构建成功后才删掉本地副本。文件名是 `<slug>-<内容哈希>.<扩展名>`：同一张图选两次
  只传一次，发布失败重试会直接命中服务器上已有的文件。
- **附件管家** —— 兜底工具：列出附件库、标出已没有文章引用的文件，不需要的移进站点根之外的
  `.blogpad-trash/`，还能还原或彻底删除。任何删除都必须你先看到列表再确认。
- **文章回收站** —— 删除的文章不直接消失：按批次整体搬进站点根之外的 `.blogpad-trash/posts/`，
  文章和它引用的附件一起过去。「仅还原」搬回文件并把 `draft` 改回 `true`，「还原并构建」保持
  原状态重建，适合误删已发布文章。长按菜单只剩「发布」与「删除」，临时下线统一走回收站——
  「转为草稿」只改一行 front matter，文件和线上产物都还在，既撤不下来也没删掉，不再是下线手段。
- **封面单独归类** —— 封面进独立子目录，只写进 front matter 的 `image`，不进正文。
- **封面裁剪** —— 选完封面进裁剪页：可用预设比例，也可等比或自由拉伸，切割框能拖、能贴到
  图片左右边缘，框内实时显示当前比例。封面先落在暂存区，杀后台后回到发布页仍能恢复；点封面
  小图可看全屏大图。
- **预览能看真图** —— 远端 `https://` 图片与封面会真正解码显示；站内相对路径发布前无法取到，
  预览标注"发布后可见"而不是报错。
- **SSH 传输** —— 同一会话内完成 SFTP 上传与远程命令执行，支持密钥（OpenSSH `ed25519` /
  `rsa`）与密码两种认证方式。
- **主机指纹固定** —— 首次连接需核对 SHA-256 指纹，确认后写入配置；指纹变化时拒绝连接。
- **构建失败自动回滚** —— 远端构建返回非零时，新增文件被删除、覆盖文件恢复原内容，
  不会留下构建失败的半成品文章。
- **草稿模式** —— 写入 `draft: true`，不生成链接。
- **编辑内容自动缓存** —— 新建的文章边写边缓存，切后台或退出后下次打开自动恢复；发布成功后
  缓存清空，不会把发出去的旧稿又弹回来。
- **配置加密存储** —— 主机、凭据、私钥整体序列化为 JSON，用 Android Keystore 中的
  AES-256-GCM 密钥加密后存入 `SharedPreferences`；应用已关闭系统备份。

## 系统要求

| 项 | 要求 |
|----|------|
| 安卓 | 8.0（API 26）及以上 |
| 服务器 | 任意开启 SFTP 的 SSH 服务 |
| 站点 | 服务器上的 Hugo 工程，且构建工具链已安装 |
| 构建 | JDK 17、Android SDK 34、Gradle 8.13 |

## 安装

从 [Releases](../../releases) 页面下载 APK 安装。应用不预置任何服务器配置，首次使用需自行填写。

## 配置

打开「设置」，共两组字段。

### 连接

| 字段 | 默认值 | 说明 |
|------|--------|------|
| 主机 | — | 服务器域名或 IP |
| 端口 | `22` | SSH 端口 |
| 用户名 | — | SSH 登录用户 |
| 认证方式 | 密钥 | 密钥 / 密码切换 |
| 私钥 | — | 可直接粘贴或从文件导入，仅支持 OpenSSH 格式，不支持 `.ppk` |
| 私钥口令 | — | 有口令的密钥才需要填写 |
| 密码 | — | 选择密码认证时使用 |

填好后点「测试连接」。首次连接会显示服务器指纹，确认后才写入信任；之后每次发布都会校验该指纹。

### 站点

| 字段 | 默认值 | 说明 |
|------|--------|------|
| 站点根目录 | — | 服务器上 Hugo 工程的绝对路径 |
| 文章目录 | `content/post` | 相对站点根目录 |
| 构建命令 | `hugo --gc --minify` | 上传完成后在站点根目录执行 |
| 站点地址 | — | 用于拼接文章链接的基础地址 |
| 链接模板 | — | 可选，如 `https://example.com/posts/{slug}/`，`{slug}` 会被替换 |

注意：

- 构建工具不在非交互 shell 的默认 `PATH` 中时，构建命令要写绝对路径，例如
  `/usr/local/bin/hugo`。
- 设置了链接模板时优先使用模板；未设置时按 `<站点地址>/archives/<slug>/` 拼接。

### 附件库

| 字段 | 默认值 | 说明 |
|------|--------|------|
| 附件库目录 | `static/upload` | 相对站点根，必须在 `static/` 下 |
| 按类型分子目录 | 开 | 开启后按下列子目录分类存放 |
| 分类子目录 | `images,videos,audio,covers,files` | 顺序固定：图片、视频、音频、封面、其他；前四个必填，第五个留空则用 files |

附件管家（设置页「打开附件管家」）会把不再被任何文章引用的文件单独标出来，移走时进站点根外的
`.blogpad-trash/<批次>/原路径`，不直接删；那里可还原，也可彻底删除。

注意：

- 公开路径由物理路径推导：`static/upload/images` 对应 `/upload/images/...`，域名由站点
  `baseURL` 补全，不需要再单独配 URL 前缀。
- 拒绝绝对路径、`..` 以及 Hugo 的 `assets/` 目录：`assets/` 是 Hugo Pipes 的资源目录，
  直接引用会 404，只有 `static/` 会被复制到站点根。
- 视频和音频插入的是 HTML 标签，站点没开 `markup.goldmark.renderer.unsafe = true` 时会被
  Hugo 丢弃；图片和封面用标准 Markdown，不受影响。

## 使用

1. 打开应用即文章列表。点「新建」写新文章，或点任一条目进入编辑。
2. 编辑页只有标题、正文和「＋ 附件」。选图片、视频或音频后，文件先复制进应用私有暂存区，
   光标处只插入一条占位引用；此时服务器上什么都不会变，反复换图也不会污染远端。
3. 点右上角「完成」进入发布页：slug 由标题生成候选（默认折叠，点开可改）；分类、标签从服务器
   已有集合里点选，末尾「＋ 新建」可加新词；封面选一张，只写进 front matter 的 `image`。
4. 点「存为草稿」写 `draft: true`、不生成链接；点「发布」则先一次性上传全部附件、把正文里的
   占位替换成站内地址，再写 `.md` 并在服务器上执行构建。
5. 构建失败会回滚文章文件；附件若已上传，同内容重试会直接命中，不会重复占空间。
6. 发布成功后状态栏显示远端路径、文章链接与构建输出尾部内容，链接可一键复制，暂存区副本清掉。

## 从源码构建

```bash
# 需要 JDK 17 与 Android SDK 34
echo "sdk.dir=/path/to/android-sdk" > local.properties
gradle :app:assembleRelease
# 产物：app/build/outputs/apk/release/app-release.apk
```

也可直接用 Android Studio 打开工程。`local.properties` 不纳入版本管理。

## 安全说明

应用会在所配置的服务器上执行 shell 命令，因此所用账号应做最小化授权。

- 建议新建专用部署账号，不要复用个人或管理账号。
- 将该账号的可访问范围限制在站点目录与构建所需的少量命令上，可配合受限 shell 包装脚本，
  或 SSH 的 `command=` / `ForceCommand` 规则。
- 构建命令与文章目录是自由文本，会原样拼入 shell 命令；应自行控制其内容，不要拼接不可信输入。
- 凭据除用于 SSH 认证外不会离开设备；应用不上传任何数据到第三方服务，也不含统计与遥测。

## 工程结构

```
app/src/main/java/io/github/aixtin/blogpad/
├── ConfigStore.kt      # 配置模型、Keystore 加密、持久化、站点地址归一化
├── PostListActivity.kt # 文章列表：拉取远端目录、渲染条目、进入编辑、长按发布或删除
├── PostRepository.kt   # 远端读写、slug 改名、构建失败回滚、回收站搬运
├── MainActivity.kt     # 编辑页：新建与编辑两种模式、附件暂存与占位、草稿缓存
├── PublishMetaActivity.kt # 发布页：slug/分类/标签/封面、封面预览与链接预览
├── AttachmentInbox.kt  # 附件暂存区：私有目录落盘、索引、引用统计、清理
├── PublishFlow.kt      # 发布编排：批量上传 → 替换占位 → 写 md → 成功删副本
├── MediaPick.kt        # 选图/选任意文件，统一转成待暂存的 Uri
├── MediaLibrary.kt     # 附件库扫描、引用匹配、回收站（移入/还原/清空）
├── MediaManagerActivity.kt # 附件管家界面：文件与回收站两态
├── TrashStore.kt       # 文章回收站：批次目录、还原（草稿/保持已发布）、彻底删除
├── PostTrashActivity.kt # 文章回收站界面：列表、附件计数、还原与清空
├── CoverCrop.kt        # 封面解码、按比例裁剪与落盘
├── CoverCropActivity.kt # 裁剪页：预设比例、等比/自由、进入与回传
├── CoverCropView.kt    # 裁剪视图：安全边距、框内拖动、手势避让
├── CoverRatioStore.kt  # 记忆上一次使用的裁剪比例
├── CoverPendingStore.kt # 封面暂存：选完未发布时先存盘，重进发布页可恢复
├── SettingsActivity.kt # 连接与站点设置、指纹确认、附件管家与回收站入口
└── SshPublisher.kt     # SFTP 上传、远程构建、回滚、front matter 渲染
```
